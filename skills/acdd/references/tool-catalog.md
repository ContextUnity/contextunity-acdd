# ACDD MCP and CLI tool catalog

Use the active server registry and schemas as the final authority. This catalog is a compact navigation aid; repository-specific behavior and current schemas belong in that repository's reference docs.

## State lifecycle (5 MCP tools + flat CLI)

The server exports **18 built-in static MCP tools** (`9 code + 2 docs + 2 core + 5 state`) plus any optional `<domain>_<name>` plugin tools exported by external `DomainProvider` crates:

- `acdd_state(action, ...)` dispatches active-run lifecycle commands (`start` via `StateInput` mapped to `StartReq` with `spec_paths?`, `workflow?`, `worktree` / `create_worktree?`, `extend_scope`, `reopen`, `sync` via `SyncReq` with `rebind_workflow` → `SyncResp.rebound_workflow`, `subtask`, `snapshot`, `clear`, `run`) and read-only active-run queries (`status`, `list`, `show` with `artifact?` (`proof | findings | receipt | all`) and `include_profile?`, `next`, `context` with `detail?` (`compact | full`), `observability`). Out-of-workflow `roadmap` and `draft` actions are CLI-only (`acdd roadmap [SPEC_ID] [--spec <KEY>] [--all] [--tag <TAG>] [--field <K=V>] [--group-by <AXIS>] [--color <MODE>]` via `RoadmapReq`, `acdd draft <SPEC> <SLUG>` via `DraftReq.spec` + `workflow?` → `DraftResp.spec`) and fail closed in MCP with redirect hints. CLI parity: flat top-level commands (`acdd start`, `acdd draft`, `acdd status`, `acdd list`, `acdd show [--artifact proof|findings|receipt|all] [--include-profile]`, `acdd next`, `acdd roadmap`, `acdd context [--detail compact|full]`, `acdd extend-scope`, `acdd reopen`, `acdd sync`, `acdd subtask`, `acdd snapshot`, `acdd clear`, `acdd run`, `acdd tool <domain>_<name>`, `acdd validate` via `ValidateReq.explicit_workflow?` emitting `WORKFLOW_VALID`, registry-local `FEATURE_REQUIRED_BY_PRESET` in `ACDD_WORKFLOW_SCHEMA_INVALID`, or `DOMAIN_CAPABILITY_UNAVAILABLE`).
- `acdd_claim(node?, worktree?, worker_id?, force?, steal_remote?, detail?)` claims the active gate and returns its 6-tier budgeted context (`<= 10,000` bytes compact soft cap with `omitted_sections`, or up to `32 KiB` with `detail="full"`: `contract + guidance`, `unresolved_findings`, `pre_task_slice`, `dependency_receipts`, bounded `blackboard`, `context` lenses, plus `context_reset_required` after `rearchitect`).
- `acdd_verify(node?, test?, worktree?)` observes claim-bound command/check/call verification without advancing state (`execution_digest` + `candidate_tree_before`/`after`).
- `acdd_submit(node?, action, evidence?, findings?, worktree?, allow_main?)` submits `pass` or `reject` (supporting `rejection_findings.kind`: `defect | architectural_drift`) against a fresh verified trace (`acdd_verify` required first for `command:` / `call:` / `checks:` gates) and executes `save.post` (`none | commit | snapshot`), `archive`, and `prune`.
- `acdd_blackboard(action, run?, node?, recipient_node?, subtask_ref?, gate?, author?, topic?, status?, payload?, limit?, offset?, generation?, worktree?)` posts (`action="post"`) or reads (`action="read"`) `draft`, `notes`, `findings`, `blockers`, `decisions`, and `deferred` messages.
- `ListReq` (`acdd list`) and `BlackboardReq` (`acdd blackboard read`) paginate with `limit` (`1..=100`, default `50`), `offset`, and `generation` (`runs.generation` fence).
- Results default to Markdown (`ADR-0006`); request MCP `format: "json"` or CLI `--format json` when parsing structured fields.

## Discovery and search

Built-in tools accept an optional `worktree` selector (`acdd_claim` and `acdd next` bind execution affinity to the target checkout). Without a selector, keep the canonical server root regardless of active claims. Use `worktree: "."` to select that root for queries or manual worktrees, but **omit `worktree` when calling `acdd_claim` on a `git.worktrees: managed` `TaskGate`**—passing an explicit `worktree` overrides and bypasses automatic creation of `.worktrees/<run_name>-<task_ref>`, whereas leaving `worktree` unset creates/reuses the managed task worktree and returns it in `ClaimResp.worktree`.

Otherwise, search canonicalized and deduplicated Git-registered worktrees and immediate `.worktrees/` children in this order: exact directory name; literal prefix or normalized numeric prefix; literal suffix; literal substring. The first nonempty tier must be unique. Multiple candidates fail without falling through to a lower tier; empty or unmatched selectors fail.

Git-linked worktrees resolve `<primary_worktree>/.acdd/state.sqlite` and `<git_common_dir>/acdd/{repo.lock,backup.lock,traces.lock,state.bak.sqlite}` cleanly across checkouts. MCP requests do not transmit the client's current directory; CLI global `--root` selects a checkout, and `acdd claim`/`acdd next` `--worktree` takes an existing directory path.

For efficient navigation, confirm workspace and coverage with overview, reuse sufficient search previews, inspect one declaration, and explain only when relation edges are needed. Use `acdd_read(selector)` for complete symbol bodies when previews are insufficient. Triage docs with `search_docs(query="...", include_excerpt=true)` and inspect `get_doc(path_or_id, detail="compact")` outlines before reading selected sections with full content. Exact `code_map_query(operation="tests")` call paths are verified test relationships; possible calls and lexical suggestions are not. Removal analysis (`operation="prove_removal"`) is indexed static evidence, not runtime-safety proof. Lint reads stored syntax diagnostics; cycles are opt-in.

- `code_map_overview(aspects?, path?, worktree?, limit?, offset?, detail?, file_uris?, generation?)` returns workspace-wide root, components, counts, language coverage, profiles, and persisted primary/linked `coverage_by_workspace`. Provide a nonempty workspace-relative `path` (`file_path` alias) for scoped counts, languages, and paged files. Database aspects are `counts`, `components`, `languages`, `coverage_by_workspace`, `cycles`, `entrypoints`, `entrypoints_with_tests`, `topology`, `compiled_profiles`, and `metadata`. Adapter facets are `discovery`, `manifest_components`, `documentation_hubs`, and `runs` (with `'milestones'` alias). Omitted/empty aspects include all database aspects except opt-in `cycles`, plus adapter facets.
- `code_map_search(pattern, kind?, classification?, path?, exact?, include_docs?, include_preview?, include_pulse?, group_by_file?, worktree?, detail?, file_uris?, limit?, offset?, generation?)` ranks fuzzy matches with weighted Reciprocal Rank Fusion and orders module indexed-text hits after concrete matches before pagination. `exact=true` matches eligible names and qualified names without graph reads. Set `include_pulse=false` to skip top-hit pulse queries on other searches. `query` aliases `pattern`. `file_path` aliases `path`. `classification` filters to `production`, `test`, or `documentation`. `pattern="*"` needs a `path`, `kind`, or `classification` scope. CLI: `acdd query search <pattern> [--path <dir>] [--kind <kind>] [--classification production|test|documentation] [--limit N]`.
- `ast_grep_search(pattern, language?, path?, worktree?, detail?, file_uris?, limit?, offset?, generation?)` uses Tree-sitter `$NAME` and `$$$ARGS` captures (`query` aliases `pattern`; `file_path` aliases `path`; default MCP `limit` is `min(15, response.page_size)`, `12` by default). Omit `language` to infer it from `path` or search compatible indexed languages in scope (excluding `yaml`/`json`/`toml` when a programming language parses cleanly); supply `language` to force a single language. Anonymous `$$$` wildcards omit empty `""` entries from `captures`. CLI: `acdd ast grep [--lang rust] [--path file.rs] 'PATTERN'`.
- `search_docs(query, doc_type?, component?, include_excerpt?, worktree?, limit?)` searches indexed docs, guides, and ADRs (`pattern` aliases `query`; `path`/`file_path` alias `component`). Use `search_docs(query="...", include_excerpt=true)` for match-centered triage; use `get_doc(path_or_id, detail="compact", include_candidates?)` (`path`, `file_path`, `doc_id`, `selector` aliases accepted; `include_candidates` defaults to `false`) for an outline, then `get_doc(path_or_id, section="...")` for full section content. CLI: `acdd docs search <query> [--doc-type <type>] [--component <prefix>]` and `acdd docs get <path_or_id> [--detail compact|full] [--section <heading>] [--include-candidates]`.

## Inspection and hierarchy

- `code_map_inspect(selector, path?, worktree?, include_coverage?, show_doc?, show_source?, leading_lines?, max_body_lines?, source_offset?, generation?)` (`symbol` aliases `selector`; `file_path` aliases `path`) returns symbol summary, receiver metadata, exact callers/callees, verified `documented_in`, compact governing invariants, paged `analysis_gaps`, and candidate dispatch targets (`possible_calls`), with `include_coverage` off by default on both MCP and CLI (`acdd query inspect`).
- `acdd_read(path?, paths?, selector?, mode?, start_line?, line_count?, pattern?, regex?, context?, baseline?, output_file?, detail?, worktree?)` (`file_path` aliases `path`; `symbol` aliases `selector`) reads text without an index in core modes (`lines`, `raw`, `search`, `delta`; default `line_count` `100`; default `<= 9,000` bytes inline with `next_start_line` and batch `next_path_index` / `remaining_count` continuations, or `48 KiB` via `detail="full"` / `output_file`; `search` defaults to `context=0`, groups directory matches under `## <path>`, and excludes `**/archive/**` unless targeting `archive`) and respects `response.detail` (`compact` by default) on both MCP and CLI (`acdd read`). Markdown `outline` requires `docs`; code `outline` and symbol `snippet` require `code`. Active claims add `in_write_scope` (`ALLOWED` | `OUT_OF_SCOPE`) and hints. CLI parity: `acdd read [<path> | --path <path>] [--selector <sym>] [--mode <mode>] [--pattern <pat>]`.
- `acdd_read(selector, ...)` returns the complete digest-verified symbol when its serialized response fits the configured byte limit; otherwise it pages at complete source-line boundaries using explicit `generation` tokens.
- `code_map_explain(selector, path?, direction?, worktree?, include_coverage?, show_doc?, show_source?, leading_lines?, max_body_lines?, source_offset?, generation?)` (`symbol` aliases `selector`; `file_path` aliases `path`) returns endpoint IDs, query-relative direction, ownership, invariants, and candidate dispatch.
- `code_map_impact(selector?, changes?, path?, direction?, depth?, worktree?, detail?, limit?, offset?, generation?)` (`symbol` aliases `selector`; `file_path` aliases `path`) traces inbound/outbound dependencies or Git `changes` (`staged`, `unstaged`, `head`).

## Verification and utility

- `code_map_lint(target?, categories?, rules?, severity?, worktree?, detail?, limit?, offset?, generation?, format?)` (`path`/`file_path` alias `target`) runs unified architectural (`acdd-rule` / `.acdd/lint/*.yaml`, including `forbid_cycles` and `ast_pattern`), graph hygiene (`duplicates`, `dead_tails`, `cycles`), `syntax` (`syntax.parse`, `fact_budget_exceeded`, `intra_crate_type_homonym`; AST `cognitive_complexity` and `max_nesting_depth` remain in `node.details`), and `docs` lint rules (default categories `[arch, syntax, docs]`). CLI: `acdd lint [TARGET] [--categories ...] [--rule ...] [--severity ...]`.
- `code_map_analyze(target?, mode?, to?, base?, worktree?, lint?, include_cycles?)`: defaults to `mode="summary"` (empty target means workspace diagnostics; a path via `path`/`file_path`/`selector` means scoped diagnostics; read-only SQL `SELECT`/`WITH` supported), or runs read-only graph/Git modes: `hotspots` (PageRank centrality), `boundary`, `path` (shortest paths to `to`), `entrypoints`, `diff_impact` (with `signature_touched`, `uncovered_symbols`, governed `affected_docs`, optional `base`), and `cochange` (bounded Git co-change pairs with optional `base`). CLI: `acdd query analyze [TARGET] [--mode ...] [--to ...] [--base ...]`.
- `code_map_query(operation, selector?, target?, path?, direction?, level?, min_lines?, worktree?, include_coverage?, depth?, limit?, offset?, generation?)` (`symbol` aliases `selector`; `file_path` aliases `path`) returns covering test paths (`operation="tests"`, CLI `acdd query tests`), static removal checks (`operation="prove_removal"`, CLI `acdd query remove`), graph slices, unwired nodes, implementations, untested symbols, code clones/duplicates (`operation="duplicates"` using AST-statement windows), dead-code/phantom-test analysis (`operation="dead_tails"`, returning workspace-liveness-checked `phantom_tested`, `dead_tails`, and `dangling_calls` scoped by `path` or `target`), or read-only SQL (`operation="sql"`). Direct calls to retired `code_map_tests` or `code_map_prove_removal` fail closed with redirect hints to `code_map_query`.
  - Mandatory quality checks: builders and independent reviewers run `code_map_query(operation="duplicates", path=<scope>)` and `code_map_query(operation="dead_tails", path=<scope>)` (omitting `path`/`target` for workspace-wide `integration_review`) and eliminate or reject new clones, `phantom_tested` dead code, `dead_tails`, `dangling_calls`, and module import cycles.
- `acdd_guide(topic?, force?, worktree?, format?)` defaults to `query`; its `topics` index advertises enabled `lifecycle`, `acdd`, `gates`, `subtasks`, `code`, `docs`, `ast`, `adapter`, `init`, and `validate` topics. CLI: `acdd guide TOPIC`. Known disabled topics return `{}`; blackboard instructions disappear when `blackboard` (or `state`) is disabled. Follow the active workflow and claim `guidance`.
- Selector forms include canonical node IDs, paths (`src/scanner.rs`, stripping `file://`, `file:`, `./`), path+symbol (`src/scanner.rs:scan`, `Type::method`, `path + Type.method`), and path+line (`src/scanner.rs:42`, `src/scanner.rs#L42`). A `path` scope permits fallback to one resolved import binding, including re-exports. Use `get_doc` or `search_docs` for `.md` selectors.

## Documentation and invariant graph

Admitted Markdown/MDX, including spec collections configured in `specs:`, is indexed with section locations and frontmatter status (`default_doc_type` classifies files under `specs.*.path` as `contract`). Confined relative links/wikilinks create `cites_doc`/`cited_by_doc` only when one section resolves. Documentary code claims are eligible in the source document's workspace unless an explicit normalized file path confines them elsewhere.

`INV-*` declarations become invariant nodes; `governs` requires a uniquely resolved code claim within the invariant node's line span. Archived specs under `*/archive/` are excluded from default documentation search and hubs; `get_doc` remains available.

### SQL columns and joins (`code-map.sqlite`)

The code-map SQL schema is `nodes(node_id, id, kind, name, qualname, path_id, line, end_line, is_test, language, generated, details, node_hash, owner_path_id)`, `path_dictionary(path_id, path)`, `edges(src_hash, kind, dst_hash, path_id, line, evidence_id, confidence_id, occurrence_count)`, `files(path, status, digest, size, language, is_test, generated, path_hash)`, and `doc_sections(doc_id, path, section_title, doc_type, content, invariants, referenced_symbols, is_invariant)`. Paths and endpoints use integer IDs/hashes.

```sql
SELECT n.name, p.path, n.line
FROM nodes n JOIN path_dictionary p ON p.path_id = n.path_id
ORDER BY p.path, n.line, n.id;

SELECT src.name AS source, e.kind, dst.name AS target
FROM edges e
JOIN nodes src ON e.src_hash = src.node_hash
JOIN nodes dst ON e.dst_hash = dst.node_hash
ORDER BY src.id, e.kind, dst.id;
```
