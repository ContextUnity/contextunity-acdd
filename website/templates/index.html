Why ACDD

Regular agent harnesses vs ACDD

A regular agent harness runs one LLM prompt-and-tool loop and relies on prompt discipline. ACDD sits one layer higher — guiding each step, supplying exact context on demand, and requiring real proof before work lands.

Unguided Agent Harnesses

Where autonomous sessions break down

  • Instructions fade mid-session — long rules get buried or ignored as context fills up.
  • Premature "done" claims — agents stop after happy-path edits without proving callers or tests pass.
  • Fragile, low-awareness edits — blind grep loops miss downstream dependencies and contracts.
  • Silent architectural erosion — duplicated helpers, boundary violations, and stale docs accumulate.
ACDD Meta-Harness

Controlled, evidence-backed engineering

  • Step-by-step gate control — every stage is an explicit node in a verified DAG; agents cannot skip ahead or self-approve.
  • Just-in-time context — each claim injects only the contract, guidance, and invariants relevant to the current gate.
  • Proof required before advancing — transitions fail closed until tests, schemas, and independent reviews pass.
  • Continuous architecture verification — the linter and live SQLite graph guard boundaries, callers, and doc links on every change.

MCP & Worktree Orchestration

Thin coordinator prompts, self-claiming workers

  1. Inspect ready waves Resolve schedulable gate cursors and isolated Git worktrees via acdd_state or acdd roadmap.
  2. Spawn workers with a thin prompt Pass only the run ID, gate cursor, worker ID, and worktree path — never paste giant specs into chat.
  3. Worker self-claims budgeted context acdd_claim injects the exact contract, architect slice, blackboard notes, and code lenses.
  4. Verify, snapshot & hand off Edits run scoped checks via acdd_verify, save Git checkpoints via acdd snapshot, and advance to an independent reviewer. 
# 1. Start an ad-hoc fix or a multi-task spec
acdd start --goal "Fix auth parser" --workflow hotfix
acdd draft milestones auth-tokens
acdd start docs/milestones/AC-001.md --worktree

# 2. Inspect ready cursors & claim a gate
acdd -C .worktrees/AC-001 next
acdd -C .worktrees/AC-001 claim T1.build --worker dev-1

# 3. Verify scoped checks & submit
acdd exec -- cargo test --test parser_tests
acdd -C .worktrees/AC-001 verify T1.build
acdd -C .worktrees/AC-001 submit T1.build --action pass

# 4. Independent review, or headless runner
acdd -C .worktrees/AC-001 claim T1.review --worker rev-1
acdd run --jobs 4

ACDD Index

Polyglot Tree-sitter graph built for speed and freshness

Every admitted file is parsed into one incremental SQLite graph linking AST symbols, calls, documentation sections, and linked workspaces.

Extraction pipeline

Native Tree-sitter & framework manifests

Compiled grammars extract declarations, imports, calls, and receiver bindings, while declarative manifests resolve conventions across Django, HTMX, Alpine, Vue/Nuxt, and Rust frameworks. Template masking keeps HTML/Jinja line numbers exact.

Benchmark speed

Fast cold builds & 12–25ms queries

Measured on a 4,150-file polyglot corpus (72,293 nodes, 221,662 edges, 2,967 doc sections): cold build finishes in ~10.0 s median, single-file incremental delta in ~2.8 s, and warm MCP queries respond in 12–25 ms p50.

Auto-refresh & digest safety

Always fresh without manual rebuilds

Over MCP, each request verifies workspace identity and automatically runs incremental updates on edits. Symbol reads verify SHA-256 digests to prevent stale context, and CLI queries rebuild automatically if the index is missing.

Markdown headings index into BM25 sections with verified symbol governance edges surfaced on inspection. Configure linked_workspaces in acdd.yaml to resolve imports and docs across sibling repositories.

ACDD Lint

Enforce rules across code and docs in one pass

Zone rules in .acdd/lint/ and executable acdd-rule blocks inside Markdown docs compile into one deterministic check pass against your code graph.

Full acdd lint --categories all

Six verification categories

  • arch — 8 boundary primitives: allow/forbid deps, single-owner, entrypoints, traits, cycles, and AST patterns.
  • docs — frontmatter, relative links, heading anchors, symbol claims, duplicate and orphan invariants.
  • syntax — Tree-sitter parse errors, type homonyms, and production file-length ceilings.
  • duplicates — diff-aware AST clone detection with graph-ranked reuse hints on verification.
  • dead_tails — unreachable symbols, phantom-tested helpers, and unresolved calls.
  • cycles — strongly connected call and import cycles across modules and crates.

Default sweep runs arch, syntax, and docs; pass --categories all for all six.
