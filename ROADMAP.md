# ContextUnity ACDD Roadmap

ContextUnity ACDD evolves around one local-first Rust workspace: precise Tree-sitter code and documentation navigation (`acdd-index`), a domain-agnostic `GateProfile` (`version: 2`) verification state machine (`acdd-state`), and a strict leaf boundary (`acdd-core`) hosting `DomainProvider` extensions. Admitted commitments, task scopes, and dependency edges live in [milestones](docs/milestones/README.md); exploratory studies live in [plans](docs/plans/README.md); shipped releases through `v0.7.1` are recorded in [`CHANGELOG.md`](CHANGELOG.md) and [archived milestones](docs/milestones/README.md).

## `v0.8.0` (Next): Universal Specs, Swarm & Engine Changes

- **Universal Spec Schemas, Named Path Sets & Spec-Driven Repository Memory ([AC-006](docs/milestones/AC-006-universal-repository-memory-synthesis.md))**: Profile-declared `specs:` schemas (frontmatter `spec:`, default `contract`) with named items, `SchemaDef` validation, cross-Spec DAG, and frontmatter `spec_deltas` verified by `spec.deltas_applied`; profile `paths:` sets referenced as `paths.<name>` in gate `scope:` and `context:` replacing hardcoded layout and `docs.instructions` / `docs.adrs`; repository memory as the embedded `memory` schema written by a single-role `memory_synthesis` gate and delivered through `paths.memories` ([ADR 0014](docs/adr/0014-declarative-spec-schemas-and-items.md)).
- **Unified Swarm Gates, Peer Board Coordination & Post-Build-Delivery Gate Engine Audit ([AC-005](docs/milestones/AC-005-unified-swarm-gates-and-peer-board-coordination.md))**: Replaces `- tasks:` with one unified `GateDef.mode: linear | parallel | swarm` engine model, recursive `GateDef.coordinator` groups, `roles:` renamed to `agents:` with explicit worker self-claim, mutually exclusive grouped `save:` variants (including `save: handoff` with `scope_mode` and `repack: none | linear | by_task | last | squash`), `GateDef.with` multi-source collection binding (`spec.tasks | blueprint.tasks`, `input.channels`, `poll.items`, `{ count: N }`), extended native `GateDef.when` expressions, lock-free `save: none` SQLite CAS vs. disjoint-scope/worktree isolation for mutating gates, barrier rejection consolidation, `@mention` + `thread_id` + zero-token `acdd_blackboard` `wait`, and end-to-end audit of all post-build-delivery gate transitions (`run_tests`, `polish`, `integration_review`, `handoff`).

## Later: Observability & Reactive Automation

- **CLI MCP Split & Read-Only Local Observability ([AC-007](docs/milestones/AC-007-unified-observability-board-otlp-and-metrics.md))**: Explicit `acdd mcp` for session-scoped `stdio` MCP (`install.sh` and adapter updates with safe transition handling) separated from `acdd serve [--webui] [--telemetry]` bound strictly read-only on `127.0.0.1` (`--webui` Live Gate Board UI `GET /`, `GET /api/*`, `GET /events` SSE rendering `AC-005` `linear | parallel | swarm` trees and `@mention` threads; `--telemetry` headless `GET /metrics` bounded-cardinality Prometheus `0.0.4` exposition + incremental OTLP/HTTP JSON trace relay from `traces.jsonl`; default `acdd serve` launches both together with zero inbound state mutations).
- **Zero-Daemon Reactive Core ([AC-008](docs/milestones/AC-008-always-on-reactive-triggers-and-deferred-approvals.md))**: `AgentDef.mode: manual` sleep-at-zero-tokens deferred approvals (resumed via CLI/MCP `approve`/`reject`), `spawner.rs` `env_allowlist` secret scrubbing, claim `lease_expires_at` TTLs, durable SQLite `timers` (`v2 -> v3` migration) and one-shot `acdd tick` pulse (`systemd.timer` / `launchd` / `cron` / CI with `0` idle RAM), durable `inbox` (`dedup_key` + `coalesce_window`) dispatching through `AC-005` concurrent CAS `swarm` execution (`repo.lock` strictly when `save != none`), and paced idempotent `outbox` notifications.

## Future: Authenticated Ingress & Ecosystem Extensions

- **Authenticated Network/IPC Ingress, Interactive Web UI & Streamable HTTP MCP ([AC-009](docs/milestones/AC-009-authenticated-ingress-interactive-webui-and-http-mcp.md))**: Upfront `ADR-0013` Transport & Security layer (`Host`/`Origin` validation, constant-time scoped Bearer tokens, per-source HMAC-SHA256 webhook verification with replay windows, body byte caps, rate limiting), confined `.acdd/acdd.sock` (`0600`, OS-UID auth), `acdd serve --interactive` authenticated Web UI approvals and `@mention` blackboard steering, `acdd serve --incoming` `POST /events` webhook listener, `acdd mcp --http` Streamable HTTP MCP (`POST/GET /mcp` with `Mcp-Session-Id` and token-bound `worker_id` identity), and unified `acdd up` supervisor (`webui`, `telemetry`, `socket`, `incoming`, `mcp_http`, `sleep_until(next_timer)` loop).
- **Thin Ecosystem `DomainProvider` Shim-Crates (`crates/acdd-domain-*`)**: Modular domain crates depending only on `acdd-core` and proven Rust ecosystem libraries (such as OpenAPI diff verifiers, SQL migration linters, and JSON Schema/policy evaluators) plugged into `GateProfile` verification gates without modifying `acdd-state` or `acdd-index`; see the [domain extensions guide](docs/architecture/domain-extensions.md).
