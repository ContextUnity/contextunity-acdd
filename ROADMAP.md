# ContextUnity ACDD Roadmap

ContextUnity ACDD evolves around one local-first Rust workspace organized into three clear systems over a strict leaf (`acdd-core`): Tree-sitter code and documentation navigation (`acdd-index`), declarative spec parsing, validation, and roadmap DAG (`acdd-spec`), and a domain-agnostic `WorkflowDef` (`version: 2`) verification state machine (`acdd-state`). Admitted commitments, task scopes, and dependency edges live in [milestones](docs/milestones/README.md); exploratory studies live in [plans](docs/plans/README.md); shipped releases through `v0.7.1` are recorded in [`CHANGELOG.md`](CHANGELOG.md) and [archived milestones](docs/milestones/README.md).

## `v0.8.0` (Next): Three-System Architecture, Universal Specs & Swarm Engine

- **Extract `crates/acdd-spec`, Three-System Presets & `workflow`/`spec` Cutover ([AR-006](docs/milestones/AR-006-acdd-spec-crate-and-workflow-cutover.md))**: Extracts `crates/acdd-spec` (`acdd-core` → `acdd-spec`, shared cleanly by `acdd-index` and `acdd-state`), renames `acdd.yaml` top-level `profile:` (`SubsystemPreset`) to `preset:` (`index` / `spec` / `state` / `full` / `minimal`), cuts over `.acdd/profile.yaml` + `.acdd/profiles/` → `.acdd/workflows/default.yaml` + `.acdd/workflows/*.yaml` (`workflows_dirs:`, `workflow:`, `--workflow`, `--rebind-workflow`, `--spec`, `acdd draft <spec>`, `SpecConfig`, `crates/acdd-state/src/workflow/`, `WorkflowDef`, `ACDD_WORKFLOW_SCHEMA_INVALID` with fail-closed redirect hints on legacy names), trims embedded workflows to `base` / `code` / `documentation` (moving `audit`, `spec_planning`, and `hotfix` into `skills/acdd/references/acdd-workflow-examples/`), and reconciles `ADR 0001`, `ADR 0003`, `docs/reference/workflows.md`, and `AGENTS.md` routers.
- **Universal Specs, Explicit Spec/Path Lenses, Multi-Spec Runs, Roadmap Customization & Repository Memory ([AC-006](docs/milestones/AC-006-universal-repository-memory-synthesis.md))**: Built on `AR-006`; single `acdd.yaml` `specs:` registry (inline, built-in `contract`/`memory` bases, or external `.acdd/specs/*.yaml` via `specs_dirs:`, named `items:` collections, 3-step `SchemaDef` validation, `workflow:` binding, explicit `roadmap: true | false`, cross-Spec DAG, and `spec_deltas` verified by `spec.deltas_applied`); `acdd start [SPEC ...]` attaching `0..N` input specs to one workflow (`ClaimResp.contract.attached_specs[]`) and `docs.specs` validating `0..M` output specs; explicit `specs.<name>` and non-spec workflow `paths.<name>` in `scope:`/`context:` with documented 4-tier deterministic relevance ranking (`ADR 0006` + `ADR 0014`); `acdd.yaml` `roadmap:` display config (`color`, `badges`, `group_by`), ANSI CLI output (`NO_COLOR`/`--color`), and `--spec`/`--all`/`--tag`/`--field`/`--group-by` filters; repository memory as the built-in `memory` Spec written by a single-role `memory_synthesis` gate (`scope: [specs.memories]`) and delivered via `context: [specs.memories]` ([ADR 0014](docs/adr/0014-declarative-spec-schemas-and-items.md)).
- **Unified Swarm Gates, Peer Board Coordination & Post-Build-Delivery Gate Engine Audit ([AC-005](docs/milestones/AC-005-unified-swarm-gates-and-peer-board-coordination.md))**: Replaces `- tasks:` with one unified `GateDef.mode: linear | parallel | swarm` engine model, recursive `GateDef.coordinator` groups, `roles:` renamed to `agents:` with explicit worker self-claim, mutually exclusive grouped `save:` variants (including `save: handoff` with `scope_mode` and `repack: none | linear | by_task | last | squash`), `GateDef.with` multi-source collection binding (`spec.tasks | blueprint.tasks`, `input.channels`, `poll.items`, `{ count: N }`), extended native `GateDef.when` expressions, lock-free `save: none` SQLite CAS vs. disjoint-scope/worktree isolation for mutating gates, barrier rejection consolidation, `@mention` + `thread_id` + zero-token `acdd_blackboard` `wait`, and end-to-end audit of all post-build-delivery gate transitions (`run_tests`, `polish`, `integration_review`, `handoff`).

## Later: Observability & Reactive Automation

- **CLI MCP Split & Read-Only Local Observability ([AC-007](docs/milestones/AC-007-unified-observability-board-otlp-and-metrics.md))**: Explicit `acdd mcp` for session-scoped `stdio` MCP (`install.sh` and adapter updates with safe transition handling) separated from single-workspace `acdd serve [--webui] [--telemetry]` bound strictly read-only on `127.0.0.1` (`--webui` Live Gate Board UI `GET /`, `GET /api/*`, `GET /events` SSE rendering `AC-005` `linear | parallel | swarm` trees and `@mention` threads, interactive Architecture Map & Live Agent Lens via `GET /api/map` with PageRank centrality, AST complexity hotspots, cycle/dead-tail overlays, and Planned Specs Blast-Radius overlay, plus single-project Specs/Roadmap wave projection `GET /api/roadmap`, confined Markdown viewer `GET /api/docs`, and loopback-only task-scoped diff viewer `GET /api/diff`; `--telemetry` headless `GET /metrics` bounded-cardinality Prometheus `0.0.4` exposition + incremental OTLP/HTTP JSON trace relay from `traces.jsonl`; default `acdd serve` launches both together with zero inbound state mutations).
- **Zero-Daemon Reactive Core & Pause-and-Call Child Runs ([AC-008](docs/milestones/AC-008-always-on-reactive-triggers-and-deferred-approvals.md))**: `AgentDef.mode: manual` sleep-at-zero-tokens deferred approvals (resumed via CLI/MCP `approve`/`reject`), `spawner.rs` `env_allowlist` secret scrubbing, claim `lease_expires_at` TTLs, durable SQLite `timers` (`v3 -> v4` migration) and one-shot `acdd tick` pulse (`systemd.timer` / `launchd` / `cron` / CI with `0` idle RAM), durable `inbox` (`dedup_key` + `coalesce_window`) dispatching through `AC-005` concurrent CAS `swarm` execution (`repo.lock` strictly when `save != none`), pause-and-call cross-workflow child runs (`parent_run_id` + `waiting_on_run_id`, `max_run_depth`, one unified `pause_and_spawn_child_run` transition for declarative `GateDef.spawn_run` governed by `GateDef.save` and ad-hoc `acdd start --parent-run` waking paused parent runs with child receipts/outputs at zero tokens), and paced idempotent `outbox` notifications.

## Future: Authenticated Ingress & Ecosystem Extensions

- **Authenticated Network/IPC Ingress, Multi-Project Folder Hub, Interactive Web UI, Streamable HTTP MCP & Supervised `services:` ([AC-009](docs/milestones/AC-009-authenticated-ingress-interactive-webui-and-http-mcp.md) — reshape before execution)**: Upfront `ADR-0013` Transport & Security layer (`Host`/`Origin` validation, constant-time scoped Bearer tokens, per-source HMAC-SHA256 webhook verification with replay windows, body byte caps, rate limiting), confined `.acdd/acdd.sock` (`0600`, OS-UID auth), validated multi-project folder registry (`WorkspaceRegistry`: `acdd workspace`, `~/.acdd/workspaces.yaml`, `--project` / `--projects-file` with per-project runtime/token/path isolation, Portfolio Web UI `GET /api/projects`, and `/p/{project_id}/*` scoped views), `acdd serve --interactive` authenticated Web UI approvals and `@mention` blackboard steering, `acdd serve --incoming` `POST /events` webhook listener, `acdd mcp --http` Streamable HTTP MCP (`POST/GET /mcp` and `/p/{project_id}/mcp` with `Mcp-Session-Id` and token-bound `worker_id` + project identity), and unified `acdd up` supervisor (`webui`, `telemetry`, `socket`, `incoming`, `mcp_http`, `sleep_until(next_timer)`, plus workflow-declared companion `services:` with `ready_check`, `env_allowlist`, scoped socket/HTTP access, and clean `SIGTERM` teardown).
- **Thin Ecosystem `DomainProvider` Shim-Crates (`crates/acdd-domain-*`)**: Modular domain crates depending only on `acdd-core` and proven Rust ecosystem libraries (such as OpenAPI diff verifiers, SQL migration linters, and JSON Schema/policy evaluators) plugged into `GateProfile` verification gates without modifying `acdd-state` or `acdd-index`; see the [domain extensions guide](docs/architecture/domain-extensions.md).
